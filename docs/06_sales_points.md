## 단계 시작 방향성 제안
1. **실용적 문제 해결 + 명확한 행사정보 (추천·선택)**
2. 강사 인지도 중심
3. 신기술 선점 중심
4. 희소성·긴급성 중심
5. 사용자 정의(직접 입력)

**결정 기록:** 응답을 기다리지 않고, 이미 제공한 포스터·문구·디자인 사양서에 가장 부합하는 추천안을 가정하여 진행했습니다.

| 페르소나 | 참여하고 싶어지는 지점 | 결정 방해 요소 | 정확한 카피 대응 |
|---|---|---|---|
| 긍정 | 자료와 대화 관리 방법을 배울 수 있다 | 기능 소개만 듣는 줄 모름 | 기능 이해 → 관리 → 적용 |
| 부정 | 범위가 GPT 프로젝트로 구체적이다 | 실제 업무와 연결되나 의심 | 목회와 실제 업무 적용 방향 소개 |
| 거부 | '매번 처음부터 설명'이 자기 경험과 일치 | 불편을 못 느끼면 무관심 | H1 질문 + 상황 3개 |
| 신청 | 날짜·ZOOM·주최가 바로 보인다 | 신청 과정 복잡 | 5곳의 동일한 공식 폼 링크 |
| 관망 | 필요한 주제인지 30초 내 판단 | 참가비/실습 미확인 | 명확한 개요 + '주최 측 확인' 표기 |

## 실제 이익·증거 구분
- **제공된 사실:** GPT 프로젝트 활용방법을 강사가 안내합니다. 자료·대화의 체계적 관리 및 목회·실제 업무 적용을 다룹니다.
- **고객에게 제안하는 기대:** 반복 설명을 줄일 수 있는 방향을 이해해 볼 수 있습니다. 이는 참가 후 확정 성과가 아닙니다.
- **제공되지 않은 것:** 무료, 수료증, 후기, 인원, 강사의 공식 자격/경력, 실제 실습, 자료 제공 여부.

## 배제한 전술
허위 마감시간, 가짜 선착순, 신뢰 없는 리뷰, 참가비 할인, 성과 보장 수치를 사용하지 않습니다.


## 실패 시나리오 및 대응
1. **가격과 접속 절차 미확인으로 신청을 망설임** → 신청폼 또는 주최 측의 확정 정보 확인 후 FAQ와 세부 안내를 업데이트합니다.
2. **사진·문구가 작은 화면에서 겹침** → 375px뿐 아니라 320px까지 화면 캡처와 넘침 검사를 반복합니다.
3. **신청폼 접근이나 링크 전달에 장애 발생** → 주최 측이 실제 모바일 기기에서 폼을 최종 확인하고 링크를 교체·안내합니다.
