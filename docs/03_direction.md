## 단계 시작 방향성 제안
1. **고객 문제를 앞세우는 신청 전환형 (추천·선택)**
2. 강사 중심 신뢰형
3. 교육 커리큘럼 중심형
4. 단일 포스터 재현형
5. 사용자 정의(직접 입력)

**결정 기록:** 응답을 기다리지 않고, 이미 제공한 포스터·문구·디자인 사양서에 가장 부합하는 추천안을 가정하여 진행했습니다.

## 3-1. 이 랜딩에 맞는 업종
1. **목회 현장 중심 AI 실무 세미나 (추천)**
2. 일반 AI 생산성 강의
3. 교회 조직 교육 기관
4. 생성형 AI 소프트웨어 컨설팅
5. 사용자 정의
선택: 1. 제공된 행사명이 목회AI연구소 세미나이고 목회 적용을 안내합니다.

## 3-2. 이 랜딩으로 최종 얻고 싶은 것
1. **구글폼 실제 신청 클릭 (추천)**
2. 행사 조회수 증가
3. 브랜드 소개 페이지 체류
4. 추후 강의 문의
5. 사용자 정의
선택: 1. 폼 제출 완료 데이터는 현재 사이트가 관측하지 못하므로 CTA 클릭과 실제 신청 제출을 구분합니다.

## 3-3. 고객에게 전달할 것
1. **반복 설명 대신 GPT 프로젝트로 자료·대화를 정리하는 방법 (추천)**
2. 최신 GPT 기능 전체 소개
3. 강사의 경력·실적 중심 설명
4. AI 사용 불안 해소 중심 정서 카피
5. 사용자 정의
선택: 1. 안내문과 일치합니다.

## 전환 동선
고객 불편 공감 → 구체적 배울 내용 3가지 → 날짜·진행 방식 명시 → 신청 링크 반복. 과장된 '변화 보장'은 제거했습니다.
## 컬러 승인 현황
원본과 디자인 사양에서 흰색 + 깊은 남색 + Soft Fusion이 일치하여 추천으로 적용했습니다. 원본 로고와 최종 팔레트는 사용자의 최종 확인 대상으로 남깁니다.


## 실패 시나리오 및 대응
1. **가격과 접속 절차 미확인으로 신청을 망설임** → 신청폼 또는 주최 측의 확정 정보 확인 후 FAQ와 세부 안내를 업데이트합니다.
2. **사진·문구가 작은 화면에서 겹침** → 375px뿐 아니라 320px까지 화면 캡처와 넘침 검사를 반복합니다.
3. **신청폼 접근이나 링크 전달에 장애 발생** → 주최 측이 실제 모바일 기기에서 폼을 최종 확인하고 링크를 교체·안내합니다.
