## 단계 시작 방향성 제안
1. **교육 세미나 공감형 전환 템플릿 (추천·선택)**
2. 단일 이벤트 정보형
3. 기능 나열형
4. 브랜드 스토리형
5. 사용자 정의(직접 입력)

**결정 기록:** 응답을 기다리지 않고, 이미 제공한 포스터·문구·디자인 사양서에 가장 부합하는 추천안을 가정하여 진행했습니다.

## 블록 구조
```text
A. Header: [주최자명] + 바로 신청
B. Hero: [카테고리 라벨] / [정확한 행사명] / [고객 문제 질문 H1]
        [핵심 해결 방향] / [상세 한 문장] / [일시·장소 칩] / [CTA] / [강사 사진]
C. Pain: [반복되거나 불편한 고객 상황 3개]
D. Solution: [기능 이해] / [관리] / [업무 적용] 형태의 3단계
E. Details: 주제 / 강사 / 일시 / 장소 / 주최 / 신청
F. FAQ: 행사에서 확실히 확인되는 질문만
G. Closing CTA: 문제 해결 방향 한 문장 + 반복 신청
H. Mobile sticky CTA: 날짜 요약 + 즉시 신청
```
## 컴포넌트별 빈 템플릿
| 슬롯 | 템플릿 변수 | 필수 검증 |
|---|---|---|
| 행사명 | `{{event_title}}` | 사용자 확정 문구 |
| 문제형 헤드라인 | `{{pain_question}}` | 실제 문제와 일치하는지 |
| 해결 실마리 | `{{mechanism}}` | 가능한 방법이지 확정 성과 아님 |
| 사진 | `{{speaker_photo}}` | 실제 제공/사용 허가된 파일 |
| 일정 | `{{event_datetime}}` | 연도·시간대 재확인 |
| 장소 | `{{venue}}` | 온라인/오프라인 구분 |
| CTA | `{{form_url}}` | 실제 열림 확인 |
| 주최 | `{{organizer}}` | 다른 단체와 혼동 금지 |
| 비용 | `{{price_verified}}` | 미확인 시 노출하지 않음 |

## 반응형 규칙
- PC(1280): 문제형 H1 좌측, 인물 우측, CTA와 시간 정보 한 시선 안.
- 태블릿(768): H1 좌측을 유지하되 얼굴·버튼이 겹치지 않도록 인물 영역 이동.
- 모바일(375): H1 → 설명 → 시간 → CTA → 실제 사진 순서. 고정 신청 버튼은 별도 배치.

## 재사용 범위
행사명, 고객 문제, 혜택 설명, 사진, 주최자, 날짜, 폼 URL만 치환하면 다른 실무 교육 세미나에 적용할 수 있습니다.


## 실패 시나리오 및 대응
1. **가격과 접속 절차 미확인으로 신청을 망설임** → 신청폼 또는 주최 측의 확정 정보 확인 후 FAQ와 세부 안내를 업데이트합니다.
2. **사진·문구가 작은 화면에서 겹침** → 375px뿐 아니라 320px까지 화면 캡처와 넘침 검사를 반복합니다.
3. **신청폼 접근이나 링크 전달에 장애 발생** → 주최 측이 실제 모바일 기기에서 폼을 최종 확인하고 링크를 교체·안내합니다.
