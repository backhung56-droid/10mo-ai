## 단계 시작 방향성 제안
1. **ZIP+HTML+검수 캡처+MD 전체 보관 (추천·선택)**
2. HTML 파일만 제공
3. 이미지만 제공
4. 배포까지 자동 진행
5. 사용자 정의(직접 입력)

**결정 기록:** 응답을 기다리지 않고, 이미 제공한 포스터·문구·디자인 사양서에 가장 부합하는 추천안을 가정하여 진행했습니다.

## 구성
- `landing/`: 정적 페이지 HTML/CSS/JS, 웹용 에셋.
- `docs/`: Phase 0~13 상세 기획, 자산, 검수 및 기록.
- `preview/`: 세 가지 반응형 전체/첫 화면 캡처 및 검사 코드.
- `references/`: 제공 원본 포스터 및 디자인 사양서.
- `pipeline.py`: 산출물 유효성 점검, 에셋 재준비(기존 에셋 활용 또는 추출), 재스크린샷(환경 가능 시) 및 ZIP 생성.
- `process_log.md`: 의사결정·가정·수정·품질 판정.

## 현재 상태
- 반응형 랜딩 구현 완료.
- 4개 크기 화면 출력, 5개 신청 링크와 내부 동작 검증.
- 실제 사이트 온라인 배포는 하지 않았음.
- 독립 승인 목업 대조 및 참가비·접속 절차·실습 범위는 미확인.

## 다음 사용자 확인 항목
1. 참가비(무료 여부 포함).
2. 신청자에게 ZOOM 참여 링크를 보내는 방식.
3. 실제 강의 진행 방식·실습 범위.
4. 공식 원본 로고 삽입 여부와 디자인 최종 승인.


## 실패 시나리오 및 대응
1. **가격과 접속 절차 미확인으로 신청을 망설임** → 신청폼 또는 주최 측의 확정 정보 확인 후 FAQ와 세부 안내를 업데이트합니다.
2. **사진·문구가 작은 화면에서 겹침** → 375px뿐 아니라 320px까지 화면 캡처와 넘침 검사를 반복합니다.
3. **신청폼 접근이나 링크 전달에 장애 발생** → 주최 측이 실제 모바일 기기에서 폼을 최종 확인하고 링크를 교체·안내합니다.
