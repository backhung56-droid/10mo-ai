## 단계 시작 방향성 제안
1. **브라우저 화면 3종 렌더링 + 구조·동작 검수 (추천·선택)**
2. HTML 텍스트 비교만
3. 체크리스트만 사용
4. 사용자 스크린샷을 기다려 검수
5. 사용자 정의(직접 입력)

**결정 기록:** 응답을 기다리지 않고, 이미 제공한 포스터·문구·디자인 사양서에 가장 부합하는 추천안을 가정하여 진행했습니다.

## 검증 환경 및 한계
- Chromium 144 및 Playwright로 1280×900 / 768×1024 / 375×812 / 320×700 화면 캡처.
- 보안 정책상 로컬 URL 직접 탐색은 차단되어 HTML/CSS/JS와 이미지를 데이터 URI로 임베드한 **동일 렌더링 내용**을 브라우저에 주입하는 방식으로 검사.
- 이 스크린샷은 개발 산출물 자체 캡처이므로 독립적으로 승인된 목업과의 차이 측정은 불가. 아래 점수는 **내부 체크리스트 기반 임시 시각 판단**이고 전환율 수치가 아닙니다.

## 기능 검수
- `html lang=ko`, meta title/description, 스킵링크, h1 하나, image alt 제공.
- 5개 CTA 링크 모두 `https://forms.gle/vKgXhViRCCGvM8Z98`로 일치.
- 브라우저 JS 오류 0, 모든 검사 해상도에서 문서 수평 넘침 0.
- 모바일 375px 히어로 CTA y≈512px, 고정 CTA 표시.
- 클릭 후 폼 제출 완료 여부는 외부 서비스 영역이므로 이 검사로 보증 불가.

## 기준 판정
- 내부 체크리스트 85점 이상 및 항목 70점 이상은 충족.
- **독립 승인 목업 대 HTML의 1:1 일치 여부는 미판정** (독립 목업 미제공). 따라서 Phase 12 엄격 기준의 '완전 통과'로 표현하지 않습니다.
- 실제 신청 전환 성과와 Google Form의 제출 성공률은 배포 후 검증 필요.


## 실패 시나리오 및 대응
1. **가격과 접속 절차 미확인으로 신청을 망설임** → 신청폼 또는 주최 측의 확정 정보 확인 후 FAQ와 세부 안내를 업데이트합니다.
2. **사진·문구가 작은 화면에서 겹침** → 375px뿐 아니라 320px까지 화면 캡처와 넘침 검사를 반복합니다.
3. **신청폼 접근이나 링크 전달에 장애 발생** → 주최 측이 실제 모바일 기기에서 폼을 최종 확인하고 링크를 교체·안내합니다.
